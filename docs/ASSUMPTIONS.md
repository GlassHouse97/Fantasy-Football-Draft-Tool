# Assumptions

1. Phases 3 and 4 were validated on August 5, 2026. The newest completed NFL season is treated as 2025 and the first live prediction season as 2026.
2. Python 3.11 is used locally because the installed Python 3.14 runtime is newer than the supported range selected for this data stack.
3. The first release is a local, single-user redraft tool. Cloud scale, authentication, and mobile clients are out of scope.
4. nflverse is the historical performance and identity backbone. Play-by-play is not required for the first model.
5. ESPN ADP and league history arrive through user-supplied files. The project will not scrape ESPN.
6. A display-name match is never treated as a confirmed player identity without a source identifier or recorded confidence.
7. No representative league-history dataset is assumed. Championship probabilities remain disabled until an evidence-based minimum sample policy is implemented and satisfied.
8. Synthetic data is allowed only in labeled tests/demos and is excluded from production training by default.
9. Network failures should preserve prior snapshots and give a useful offline-reuse instruction.
10. R and Quarto are optional. Neither is currently installed, so Python implementation is not blocked.
11. PFR game-level snap counts distributed by nflverse are the Phase 3 participation source. An active game requires positive offense, defense, or special-teams snaps; roster status and weekly-row presence are not substitutes.
12. A feature row from season `t` predicts `t+1`. September 1 of the prediction season is the logical preseason cutoff. The 2026 archive acquisition timestamp is retained as provenance, not represented as historical availability.
13. Historical weekly or snap-count position/team evidence takes precedence. Static identity position is eligible only when the identity snapshot was acquired on or before the row's September 1 cutoff. Static birth, rookie, draft, and height fields retain source-dataset provenance. Weight remains available in the identity table but is excluded from historical features until its time semantics are established; current team, current experience, and active status are also excluded.
14. The August 2026 identity snapshot predates the September 1, 2026 live cutoff, so it safely supports live 2026 static-position fallbacks. It is not backfilled into historical entry cohorts. Historical rookie baseline performance remains unavailable until the project has a historical preseason-position archive.
15. Phase 3 baselines are deterministic heuristics, not trained ML. Current 2026 ADP is not used in historical evaluation because no cutoff-safe historical snapshot archive exists.
16. Phase 4 trains Ridge and histogram gradient-boosting regressors separately for each core position and each of points per active game, games active, and total points. Direct fantasy-point targets remain benchmarks; component-first modeling is still future work.
17. Champions are selected only from pooled 2020-2024 validation. A learned candidate must lower MAE versus the best transparent baseline and have a paired-bootstrap learned-minus-baseline 95% confidence interval with an upper bound below zero. The 2025 test is reported after selection and cannot change it.
18. Learned P10/P50/P90 values are empirical signed-residual intervals fitted from earlier out-of-fold training predictions. Coverage is measured by season, position, and projection tier, not guaranteed. Retained baselines remain point estimates with `P10=P50=P90`.
19. Historical rookie model performance is unavailable without a historical preseason-position archive. The 233 live rookie rows use explicitly unvalidated, uncalibrated, point-only transparent fallbacks and never learned estimators.
20. DuckDB and registered attempt-scoped SHA-256 hashes are the Phase 4 publication authority. The deterministic `run_id` identifies the model/data contract, and a unique `publication_id` identifies each immutable training attempt. All six Phase 4 tables are staged, audited, and promoted in one transaction so a failed forced retry preserves the prior complete publication. Tracked evaluation and registry files are convenience mirrors. The app hides the projection board unless exactly one complete run matches current upstream lineage, counts, and registered output hashes.
21. Phase 4 predicts player outcomes only. Phase 5 keeps market movement and conditional next-pick availability in separate tables and services; neither phase implements draft recommendations, mutable draft state, or a simulation engine.
22. Phase 5 production loading excludes clearly labeled synthetic fixtures by default. Duplicate manifests that point to the same immutable raw payload collapse into one stable snapshot, and repeat loads must preserve rows and fingerprints.
23. Unresolved ADP identities remain keyed to their stable source identity with nullable canonical `player_id` and recorded mapping confidence. Display name is never used as the canonical join key.
24. A movement forecast may use only observations captured at or before its as-of time. Persistence requires one dated observation; linear and exponentially weighted trends require at least three observations for the same source player. The validated single-snapshot archive therefore supports persistence only.
25. Phase 5 availability uses a continuity-corrected normal pick distribution conditional on the player still being available at the current pick. Source standard deviation is preferred, min/max-derived scale is second, and the versioned configured fallback is last. This is a transparent assumption, not a calibrated probability claim.
26. The validated Phase 5 build has no linked real-draft outcomes and only one independent production capture. Availability calibration and supervised movement or availability models remain unavailable until enough dated captures and outcomes permit chronological evaluation.
27. Phase 6 state is event-sourced. Session start, pick, undo, and replacement are append-only; replay plus stored fingerprints is authoritative, while Streamlit session state and convenience roster views are not.
28. A Phase 6 session freezes its projection pool and all model/market/rules/configuration lineage. New upstream data affects only a newly created session and never silently rewrites an in-progress draft.
29. Phase 6 consumes fantasy-points-total projections only when session scoring matches the verified projection reference's scoring-only fingerprint. Team count, starter shape, flex eligibility, bench, and draft slot may vary; a scoring change requires a rebuilt projection contract.
30. Phase 6 joins market evidence to projections only through a reviewed canonical player ID. Display name, team, and position may detect conflicts but never create a join. Duplicate canonical market IDs or incomplete required coverage block recommendation readiness.
31. State-only sessions remain valid when ADP mapping is incomplete. The current production boundary is 1,367 frozen canonical projections, 203 draftable QB/RB/WR/TE market rows, and 0 reviewed mappings, so manual drafting works while recommendation and Monte Carlo actions report `identity_mapping_required`. The other 43 archived PK/DEF rows remain auditable but are outside this ruleset's coverage denominator.
32. The `phase6-baseline-v1` simulator and recommendation weights are transparent configured assumptions, not learned opponent behavior or a calibrated team-outcome model. Controlled fixtures validate code behavior but do not establish live calibration.
33. Point-only projection rows remain deterministic in simulation and are not treated as evidence for a safer floor or higher ceiling. Seeded simulation is reproducible, not certain.
34. A Phase 6 draft recommendation score is a configurable comparison of VORP, scarcity, next-pick risk, roster fit, uncertainty, and simulated roster value. It is not a playoff or championship probability; those remain disabled.
35. Phase 7 is the next build phase for UI, data-center, league-setup, post-draft, export, and learning-center polish. Canonical identity review is an operator prerequisite, not something Phase 7 may bypass.
